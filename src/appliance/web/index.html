Sound meters

What the sound card is being given, channel by channel — taken at the output, not at the feed. Muting the box, a card that would not open, and an event that has genuinely gone quiet all read as silence here, and the line underneath says which of them it is. The meter shows what the card is being handed, so a channel the card is too narrow to take is not drawn: four bars of a signal that is not leaving the box would be worse than no bars at all.

    Picture

    The box sets this on the output itself. "Whatever the screen prefers" is right unless you are feeding a chain that needs a specific rate.

    Only applies when the room sends a composited feed — the encoder declares a 2×1 or 2×2 layout in the event. Then this box can put one of the pictures on the screen full-height instead of the wide composite with bars. A feed that is a single picture ignores this.

    On a Pi 4 the hardware H.264 decoder is what keeps the picture up without spending every core on it. Falling back to software is automatic, so this only needs changing on a box that decodes badly.

    Sound

    HDMI carries up to eight channels; a de-embedder at the campus recovers each one separately.

    0 follows whatever the feed carries.

    OBS can publish six tracks and an event carries every one it was given. This picks the one that goes to air; the rest are ignored. Track 0 unless somebody at the origin says otherwise.

    Remote access

    How this box can be reached from outside the building, so a setting can be fixed without driving to the campus. Both are optional and neither is needed for the box to play.

    The box joins this network and takes an address on it. That address is shown on the screen in the room as the remote access address, and it only answers once the box has been authorised in ZeroTier Central.

    Publishes this control page on a public hostname, with no port-forward and no static address.

    On power-up
    Updates

    Asks GitHub once each time the player starts whether a newer release exists, and shows a line under This box if one does. Nothing is downloaded and nothing installs itself; choose Do not check and no request is made at all.

    Network audio output

    Needs the open AES67 stack installed on this box, which is a separate step (scripts/player/merging-aes67.sh). Switching this on starts the daemon, sets it to come back after a power cut, creates the stream, and moves the sound onto the AES67 card — that card is what the daemon publishes, so the sound has to be going there for there to be a stream at all. Switching it off stops the stream and puts the sound back on the output device above.

    Where the stream is sent. A console receiving it has to be told the same address, unless it finds the stream by itself — this daemon announces itself over SAP, which most do.

    How wide the stream is — eight by default. It carries whatever the feed happens to contain; what is sent is the campus's business, not this box's. The width is fixed rather than following each event, because receiving consoles configure against it and would otherwise have to re-learn the stream.

    Monitoring heartbeat

    Posts a small status document every 30 seconds while playing, held or starting, every 5 minutes otherwise. Off by default — switched off, nothing is sent. A failed post is dropped, never queued, so monitoring never competes with the programme for the link.

    The collector's base address, typed in by hand, with no default. Empty means no heartbeat is sent.

    The ID the collector knows this box by — it must match the ID the token was minted for.

    Minted with the collector's mint tool. Dots mean the saved token is kept; clearing the field removes it.

    Prefer this over typing an ID and token by hand: press Connect, enter the code shown on the collector's page, and the ID and token fill themselves in when it is approved.
